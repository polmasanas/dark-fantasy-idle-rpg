# M6 Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give each hero a 12-node Common skill tree with ranks, 3 auto-cast active slots whose cooldowns keep running between fights, passives, gold respec and an auto-spend preset, saved in schema 3 and balanced by the simulation.

**Architecture:** Skill data lives in a new `skills_config.json` (authority in `Tools/BalanceSim/`, byte-identical copy in `Assets/_Game/Data/`), loaded into `SkillsConfig` and attached to `BalanceConfig.Skills`. A pure `Skills/SkillTree` handles points, ranks, loadout and respec on `CharacterState`; `Skills/SkillBuild` turns ranks into stat bonuses (through `StatInputs`) and a `SkillKit` (actives in priority order + combat passives) that `CombatEngine.Resolve` runs as more events on its existing timeline. `GameSession` keeps per-hero cooldown timers in memory and carries them across fights, gaps and offline time. Names and descriptions live in `look_config.json`; Unity only draws.

**Tech Stack:** C# 9 (Unity 6000.3.29f1), NUnit via `dotnet test Core.Tests.Dotnet`, Python 3 balance simulation, UI Toolkit.

**Spec:** `Docs/specs/2026-11-20-m6-skills-design.md` (decisions M6-1…M6-3; R2-8, R2-9, GDD §7).

## Global Constraints

- Game.Core never references UnityEngine, `System.Random` or wall-clock time; randomness only via `IRng`. C# 9 only; warnings are errors. Test first for all Core code. Tests must compile with Unity's 3.5-era NUnit (no `Is.AnyOf`) and must not use `internal` members.
- Config keys are **append-only**. New `skill_rules` section at the **end** of `balance_config.json`: `tier_points: 5, cooldown_reduction_cap: 0.5, respec_base, respec_growth, dot_tick_s: 1.0, hero_dodge_cap` (first values for respec and dodge cap from the simulation). The existing `skill_point_every_levels: 5` and `active_skill_slots: 3` stay where they are. Both copies of each config file byte-identical (tests).
- Points earned = `floor(level / 5)`; unspent = earned − sum of ranks (never stored). Tier t opens at `(t−1) × 5` points spent. Actives max rank 3, passives 5 (per node in data).
- 3 slots; slot order = priority; a ready active whose condition holds **replaces** the hero's attack; cooldown = `base × (1 − rank_cdr × (rank−1)) × (1 − min(cdr, 0.5))`.
- Cooldowns run during fights and during the respawn gap (`combat.enemy_respawn_s`), online and offline; per hero; not saved (ready after load); a switch or loadout change never resets a timer; a newly slotted skill starts ready.
- **With no ranks spent, every fight result and event is identical to M5** (golden values for the no-skill path unchanged).
- Normal enemies never kill (R2-1c); auto-spend never acts when its checkbox is off; nothing equips automatically (R2-18).
- Save schema becomes **3**; `v1.dfrs` and `v2.dfrs` keep loading; add `v3.dfrs`, never regenerate any fixture.
- New Unity files need `.meta` files committed by the owner after import.

## Review Focus

1. **A hero with ranks in a skill that is later removed from data** (unknown node ID in the save or in the loadout) → dropped on load, its points come back as unspent, no crash. Test `Load_UnknownSkillId_DroppedAndRefunded` (Task 6).
2. **Level drops below what the spent points need** (e.g. a save edited by hand, or a later change to the points rate, leaves spent > earned) → the tree is reset for free on load, never negative unspent. Test `Load_SpentAboveEarned_ResetsTree` (Task 6).
3. **Every slot holds an active whose condition never holds** (e.g. only Executioner against a fresh enemy) → the hero keeps attacking normally, no stall. Test `ConditionNeverMet_HeroKeepsAttacking` (Task 3).
4. **Cooldown reduction from several passives above the cap** → clamped at 50%, cooldown never ≤ 0. Test `CooldownReduction_ClampedAtHalf` (Task 3).
5. **Switching heroes mid-fight with skills on cooldown, then back** → the dropped fight doesn't advance the timers; each hero's timers are its own. Test `Switch_DroppedFight_DoesNotAdvanceTimers` (Task 5).

### Task 3: Active skills in combat (Core)

**Files:**
- Modify: `Assets/_Game/Core/Combat/CombatEngine.cs`, `CombatTypes.cs`
- Test: `Assets/Tests/EditMode/Core/Combat/SkillCombatTests.cs`

**Interfaces:**
- Consumes: `SkillKit`, `ActiveSkill` (Task 2).
- Produces:
  - `CombatEngine.Resolve(CombatStats player, EnemySnapshot enemy, IRng rng, bool recordEvents, SkillKit kit, double[] cooldownLeft)`; the old 4-argument overload calls it with `SkillKit.None, null`. `cooldownLeft[i]` (seconds left for `kit.Actives[i]`) is read at fight start and **written back** at fight end (remaining after the fight's duration; floor 0).
  - `CombatEventType` appends `SkillHit, SkillCrit, DotTick, BuffStart, Dodge, Heal`; `CombatEvent` gains `string SkillId` (null for normal events; constructor parameter appended with default).
  - Firing: at each hero attack time, the first active in priority order with `cooldownLeft ≤ 0` and condition true replaces the attack: run its `hit` effects (hits × percent, element replaces the Physical component, `AlwaysCrit`, `CannotMiss` = hit chance 1, crit damage + `SkillCritDamage`), set its cooldown, schedule the next attack one interval later. Skill hits never trigger Counter.
  - **Exactness:** when `kit.Actives` is empty and the kit has no passives, the loop must take the exact M5 code path (attack times `n × interval`), so results and RNG use are bit-identical.
